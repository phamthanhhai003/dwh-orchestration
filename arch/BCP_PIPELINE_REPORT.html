pull_bulk DAG · MSSQL testdb → MinIO → Hive Iceberg · Updated 2026-06-25

Giới thiệu

Báo cáo này ghi lại hiệu năng thực đo của pipeline pull_bulk — pipeline đồng bộ toàn bộ 36 bảng CDC từ MSSQL vào Hive Iceberg thông qua MinIO, sử dụng BCP làm công cụ extract. Dữ liệu được đo trên hai môi trường: DEV (giới hạn 100K rows/bảng, cluster dùng chung) và UAT (full data, disk HDD).

Mục đích chính: cung cấp baseline thời gian chạy theo từng bảng để estimate tổng thời gian Day-1 init load trên UAT và PROD, đồng thời xác định bottleneck cần tối ưu trước khi chuyển sang CDC streaming.

BCP (Bulk Copy Program) — Định nghĩa & Cách hoạt động

BCP là command-line utility đi kèm Microsoft SQL Server (mssql-tools). Chức năng: copy dữ liệu giữa SQL Server instance và file — theo hướng queryout (DB → stdout) hoặc in (file → DB).

Cách hoạt động: BCP mở kết nối TDS (Tabular Data Stream — giao thức native của SQL Server) đến database, thực thi query, và stream kết quả ra stdout dưới dạng text thuần (TSV). Không serialize qua JDBC driver, không đi qua JVM.

Resource tiêu thụ:

  • CPU (MSSQL server): query execution + serialize sang TSV text
  • CPU (client pod): grep filter stdout → pyarrow parse TSV → serialize Parquet (CPU-bound)
  • RAM (client pod): buffer pyarrow chunk in-memory trước khi upload (~250 MB/chunk ở 500K rows × avg row size)
  • Network: toàn bộ dữ liệu stream từ MSSQL pod → client pod qua cluster network (TCP/TDS)
  • Storage: không ghi disk local — Parquet chunk ghi thẳng lên MinIO qua boto3 stream upload

Kết luận

Pipeline pull_bulk đã chạy thành công end-to-end toàn bộ 36 bảng CDC trên DEV — 109 tasks (extract + parse + seal), không có failure sau khi xử lý các edge case bảng rỗng. Tổng thời gian DEV run: ~2h từ lúc trigger đến task cuối cùng seal xong.

Giai đoạn Parse chiếm phần lớn thời gian so với Extract. AAFBNK_AA010 là bảng nặng nhất: extract 360s, parse 4,517s — XML size/row lớn (~11KB/row) là nguyên nhân chính. Trên UAT, FBNK_CUSTOMER (3 GB thực) parse mất 3h36m với cấu hình 2 executors, shuffle.partitions=4.

Số liệu DEV và UAT trong báo cáo này là cơ sở để estimate thời gian Day-1 init load khi chạy full data trên từng bảng.
