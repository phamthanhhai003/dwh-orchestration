3. Chi Tiết Từng Option

✅ Option A — BCP Bulk Export

MSSQL └─ bcp queryout (1 sequential scan) └─ TSV stream → pyarrow chunks └─ parquet → MinIO raw/t24/ └─ Spark parse └─ Hive Iceberg Bronze

Pros: DB hit 1 lần duy nhất per table, disconnect sau khi xong. Memory thấp (~250MB/chunk, stream không buffer). Không bị ảnh hưởng bởi CDC inserts. Không cần index.

Cons: Single-threaded per table. Cần bcp CLI (native SQL Server tool) trong môi trường chạy.

🔵 Option B — JDBC Keyset Pagination

Spark JDBC └─ batch 1: TOP 500K ORDER BY RECID └─ batch 2: WHERE RECID > '{last_recid}' └─ batch N: ... cho đến hết └─ Hive Iceberg Bronze

Pros: Không cần tool ngoài. Clustered PK trên RECID → index seek, nhanh đều mọi batch. Checkpoint đơn giản (lưu last RECID), resume tốt nếu fail giữa chừng.

Cons: DB bị hit N lần (~160 queries/bảng 80M rows). Load DB cao hơn BCP. Cần quản lý checkpoint state.

❌ Option C — OFFSET/FETCH

Spark JDBC └─ OFFSET 0 FETCH NEXT 500K └─ OFFSET 500K FETCH NEXT 500K └─ ... └─ Hive Iceberg Bronze

Tại sao loại: CDC đang write liên tục → INSERT mới làm dịch chuyển OFFSET → miss hoặc duplicate rows giữa các batch. Ngoài ra OFFSET càng lớn MSSQL càng phải scan nhiều hơn từ đầu → chậm dần.

⚠️ Option D — RECID List Batch

Step 1: SELECT RECID FROM table → lưu toàn bộ list Step 2: loop WHERE RECID IN (batch 1000 RECIDs) └─ Hive Iceberg Bronze

Tại sao không scale: Phải lưu hàng triệu RECID strings vào memory/file. IN clause N=1000 → hàng trăm nghìn round trips cho bảng 80M rows. Đọc DB 2 lần. Overhead không cần thiết khi Keyset đã xử lý tốt hơn.

Khuyến nghị: chạy tuần tự (không parallel), pin Spark jobs vào worker-03 (RAM actual thấp nhất), schedule ngoài giờ hành chính.
